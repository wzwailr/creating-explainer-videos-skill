# v2.0.1 Release Integrity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish a reproducible `v2.0.1` whose runtime requirements are truthful and whose real HyperFrames-to-FFmpeg path is exercised in CI.

**Architecture:** Keep the existing Python lifecycle layer and JavaScript runtime. Tighten their shared compatibility contract to Node.js 22+, make `doctor` model the existing pinned `npx` render path without downloading, and add one short integration fixture that calls the real production rendering and media adapters. Build every public artifact from the same green tagged commit.

**Tech Stack:** Node.js 22/24 ESM, `node:test`, Python 3.9+, unittest, HyperFrames 0.8.15, Chrome/Edge, FFmpeg/ffprobe, GitHub Actions, npm packaging, Hatchling/Twine

**Spec:** `docs/superpowers/specs/2026-08-31-v2.0.1-release-integrity-design.md`

## Global Constraints

- Python lifecycle commands work without Node.js.
- Project, preview, render, and media commands require Node.js 22+.
- `doctor` performs no package download or paid-provider call.
- A real render is never equivalent to human release approval.
- Tag, GitHub assets, PyPI artifacts, and npm artifact must derive from one green commit.
- `v2.0.0` history is preserved; remediation ships as `v2.0.1`.
